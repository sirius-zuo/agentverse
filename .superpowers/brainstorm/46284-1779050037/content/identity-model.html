Dimension 4 — Identity & discovery

How does Aether know which agent to send a message to?

A

Named agents in a global registry

Every agent has a unique name and declares a set of capabilities. Aether maintains a registry — routing can look up agents by name ("researcher") or by capability ("summarize"). Agents can be swapped, listed, or replaced by name without changing workflow topology.

registry.get("researcher")           // by name
registry.find_capable("summarize")   // by capability

Pros

  • Dynamic routing — router picks at runtime
  • Agents swappable without rewiring graph
  • Natural fit for Phase 2 service discovery

Cons

  • Global mutable registry needs care under concurrency
B

Structural roles in a workflow graph

Agents are defined by their position in the DAG — no global registry. The graph is wired at construction time: node A's output edge points directly to node B's handle. Identity is structural, not nominal.

workflow.edge(researcher_node, writer_node);  // hardwired

Pros

  • Simple — no registry to manage
  • Compiler catches broken edges

Cons

  • Dynamic routing impossible — can't pick agent at runtime
  • Swapping agents requires rewiring the graph
C

Both — registry-backed structural graph

The workflow graph uses named references ("researcher", "writer") rather than direct handles. Aether resolves names through the registry at runtime. Edges are structural (DAG wiring) but agents are swappable because the graph holds names, not pointers.

workflow.edge("researcher", "writer");  // name-based
// registry resolves "researcher" → AgentNode at send-time

Pros

  • Static topology + dynamic resolution
  • Hot-swap agents by updating registry
  • Capability routing still possible for the router node

Cons

  • Typos in names are runtime errors (mitigated by a builder API)

My recommendation: C. Gives you static topology (the graph is explicit and inspectable) with dynamic resolution (swap agents without rewiring). The builder API can validate names at construction time, catching typos before runtime.
