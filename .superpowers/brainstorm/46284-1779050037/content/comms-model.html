How do agents communicate?

This is the most consequential architectural decision for Phase 1.

A

In-process async (Tokio channels)

All agents run in the same process. Aether passes messages via mpsc / oneshot channels. Zero serialization cost, native Rust lifetimes, simplest to build.

Pros

  • Fastest — no network hop
  • Smallest surface area
  • Natural fit for Phase 1

Cons

  • All agents share one process
  • Phase 2 clustering needs an abstraction swap
B

Transport trait (in-process now, network later)

Define a Transport trait with send(AgentMessage) and recv(). Phase 1 ships a LocalTransport backed by channels. Phase 2 swaps in GrpcTransport / HttpTransport without touching orchestration logic.

Pros

  • Clean boundary for Phase 2
  • Still fast in Phase 1
  • Testable with mock transport

Cons

  • Slightly more abstraction upfront
  • Message type must be serializable
C

HTTP/gRPC from day one

Each agent runs as an HTTP service (using avs-server). Aether is a pure network orchestrator — sends requests, awaits responses. No shared memory.

Pros

  • Phase 2 clustering is trivial
  • Agents are independently deployable now

Cons

  • Serialization + network overhead for every hop
  • Much more infra to run locally
  • Overkill for Phase 1
