Dimension 2 — Memory across agents

AgentVerse already gives every agent its own short-term memory. The question is what Aether does on top of that.

Fixed baseline (not up for debate): Every agent always owns its own short-term rolling window (SimpleMemory / AgentMemory). No agent ever reads another agent's internal conversation buffer. This is guaranteed by the AgentVerse memory trait — agents are opaque units.

The open questions are about what passes between agents and whether long-term storage is shared:

A

Output-only passing (strict isolation)

Agents exchange only final outputs — a string or structured result. Agent B never sees Agent A's reasoning trace or message history. Pure message-passing.

A completes → Result("here is the summary") → B receives as new user message
B

Context injection (output + trace)

Aether can optionally package Agent A's output plus a summary of its reasoning trace and pass that as enriched context to Agent B. Agent B's memory sees it as a pinned system context — it doesn't merge A's history, it receives a curated snapshot.

A completes → AgentContext { output, summary_of_steps } → pinned into B's memory
C

Shared long-term store (optional)

Short-term memory stays private. But Aether can wire multiple agents to the same LongTermBackend (lancedb / pgvector). Each agent writes its outputs to shared vector storage; other agents can retrieve relevant history via semantic search. Namespaced by agent so reads are scoped.

A stores result → shared vector DB (namespace: "researcher")
B retrieves relevant docs → B's AgentMemory.prime_from_long_term()

These are composable — A + C or B + C are both valid. A alone is the simplest and most isolated.
