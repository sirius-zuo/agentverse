Lightweight IPC transport options

Agents are separate OS processes. No HTTP, no network stack. What does Aether use to talk to them?

A

stdin/stdout protocol (like MCP / LSP)

Aether spawns each agent as a child process and communicates via newline-delimited JSON over stdin/stdout pipes. Aether owns the process lifecycle — it spawns, restarts, and kills agents. Zero extra dependencies.

Aether spawns: ./researcher-agent --aether-mode
→ writes JSON to agent's stdin
← reads JSON from agent's stdout
stderr → Aether's log / observability

Pros

  • Zero deps — OS pipes only
  • Aether has full lifecycle control (natural for Supervisor)
  • Maps perfectly to SpawnPolicy — PerRequest = new subprocess, Singleton = keep process alive
  • Already the MCP model — AgentVerse knows this pattern

Cons

  • Aether must spawn all agents — agents can't start independently
  • Process-per-agent overhead for large pools
B

Unix domain socket + JSON-RPC

Agents listen on a Unix socket (/tmp/aether/<name>.sock). Aether connects and sends JSON-RPC calls. Agents can start independently — Aether just connects. Much faster than TCP (no network stack), same API feel.

Agent binds: /tmp/aether/researcher.sock
Aether connects → sends: {"method":"invoke","params":{…}}
Agent responds: {"result":"…"}

Pros

  • Agents can start/stop independently of Aether
  • Faster than TCP — kernel-optimised local IPC
  • Phase 2: swap Unix socket for TCP socket → same protocol, distributed

Cons

  • Agents must manage socket lifecycle (bind, cleanup on exit)
  • Aether must poll or wait for socket to appear (service discovery)
C

Both — stdio for spawned, socket for pre-running

The Transport trait abstracts both. StdioTransport for agents Aether spawns and owns (PerRequest, Singleton under Aether control). UnixSocketTransport for agents that are already running independently. Same message protocol either way.

// same message format, different pipe
trait Transport {
  async fn send(&self, msg: AetherMessage) → Result<AetherMessage>;
}

Pros

  • Full flexibility — Aether-owned and pre-running agents
  • Phase 2: add TcpTransport without changing anything else
  • Message format is the one true coupling between Aether and AgentVerse

Cons

  • Two transport impls to ship (though both are small)

Note: In all three options, the message format (a simple JSON envelope) is the only contract between Aether and AgentVerse. AgentVerse adds a thin adapter — a mode flag that makes the agent binary speak the Aether wire protocol instead of the normal CLI interaction.
